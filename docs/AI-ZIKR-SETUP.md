# Zikr AI API

The `/api/chat` Vercel function creates a private, context-aware dhikr planning
conversation. It can add tasbih phrases and a curated set of Qur’anic duas. Duas
are selected by a fixed catalog ID; Arabic text, transliteration, Uzbek meaning,
and verse reference come from the verified catalog, not generated model text.
The user may edit a saved personal item's Arabic text, pronunciation, or meaning.
The assistant does not provide religious rulings or verify new sources.

## Production setup

1. Deploy the repository to Vercel with the repository root as the project root.
   `vercel.json` publishes `public/` and gives the chat function up to 60 seconds.
2. In the Vercel project, add `GEMINI_API_KEY` as an encrypted **Secret** in the
   Production environment. Enter the variable name in **Key** and the Gemini API
   credential from Google AI Studio in **Value**. Never paste the credential in
   chat, source code, the browser, or a committed `.env` file.
3. Redeploy after saving or changing the secret.
4. `public/zikr/ai-config.js` already points to the production `/api/chat`
   endpoint. Deploy `public/zikr/` to Firebase Hosting after frontend changes.

The server tries Gemini 3.1 Flash-Lite, Gemini 3.8 Flash, Gemini 2.5
Flash-Lite, and Gemini 2.5 Flash in order. The request uses Gemini structured
output with the approved catalog IDs as an enum, then validates every returned
schedule against the same catalog. It moves to the next model on quota,
availability, or invalid output. Google offers free access to eligible models
with per-model and account limits; eligibility, regional availability, and
quotas can change, and an API key on a billed project may incur charges.
Confirm the current terms and model access in Google AI Studio before enabling
billing.
For a clear request to add a known dua (for example, an invocation for knowledge),
the server can add the matching catalog entry if all models fail or return no
usable plan. This fallback contains only the fixed, verse-referenced entries.

The client sends up to 12 prior conversation messages (at most 8,000 combined
characters) to the function so the assistant can continue the personal plan.
The history stays in the visitor's browser and syncs with their private account
when signed in. The function validates messages and schedules before returning
them. Requests are limited to five per IP per minute per warm server instance;
this in-memory throttle is best-effort and is not durable across serverless
restarts. Set appropriate quota limits in Google AI Studio for public use.

Run the focused checks with
`node --test tests/api-chat.test.js tests/zikr-reminders.test.js`.

The Zikr API currently uses Google's Gemini API. We could not verify
“GPT-6 Luna” as a documented OpenAI API model, so it is not configured as a
model ID. If it belongs to another provider, verify that provider's API
endpoint/model ID first; additional providers require their own server-side API
key and must not expose credentials to the browser.

## Zikr reminders and account sign-in

Reminders are stored with the visitor's private Zikr data and run while the
Zikr page is open. They can repeat daily, once weekly, or on selected weekdays.
Browser notification permission is required for system notifications. The
optional per-reminder tone is generated by the page and can only play while the
page is open; websites cannot choose the operating system's notification sound.

Google and email/password sign-in use Firebase Authentication. In Firebase
Console, enable Google and (if email accounts are wanted) Email/Password under
Authentication providers, and add the deployed Zikr host to Authentication's
authorized domains. The application cannot enable these project-level settings
from frontend code. Email passwords are submitted directly to Firebase Auth;
they are not stored by this site. Firestore rules must also permit an authenticated user to access only their
own `userAppData/{uid}/apps/{appId}` documents for cross-device synchronization.
